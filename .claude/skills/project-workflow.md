# 项目开发工作流（摘录自 claude-code-best-practice）

## PR 分支规范
- 每个功能一个分支，从 master 分出
- 分支命名：pr{N}-{feature-name}
- 每个 PR 只做一件事，小而精
- Commit 信息用中文，格式：`类型: 做了什么`

## 代码质量
- 每个新功能写完后立即测试
- 前后端接口变更要保持同步
- 配置文件（密钥等）不提交到仓库
- 删除无用代码，不保留注释掉的旧代码

## 开发流程
- 先做骨架（能跑起来）→ 再做功能 → 最后打磨体验
- 每完成一个 PR 推送到 GitHub 创建 Pull Request
- PR 描述包含：功能说明、实现思路、测试方式
- 不 merge PR，保持分支开放供审查
